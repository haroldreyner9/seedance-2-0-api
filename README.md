# Seedance 2.0 API — from $0.053/s (480p), 4K at $0.58/s

**ByteDance Seedance 2.0 is live on [ArgoLink](https://argolink.io/gh-seedance-2-0-api)**: $0.053/s at 480p, $0.11/s at 720p, $0.28/s at 1080p and $0.58/s at 4K, about 25% below BytePlus's list price. Send a prompt, a first frame, a first and last frame, or up to 15 reference images, videos and audio clips; get back one 4–15 second MP4 with a soundtrack the model writes itself. It is the only Seedance generation that renders 4K.

## What is Seedance 2.0?

Seedance 2.0 is ByteDance Seed's video model with joint audio and video generation. It reads text, images, video and audio together and renders a 4–15 second clip whose sound effects, music or dialogue are generated in the same pass. ByteDance's own cloud, BytePlus ModelArk, sells it as *Dreamina Seedance 2.0* (`dreamina-seedance-2-0-260128`) beside two lighter variants, Fast and Mini, which take the same inputs and stop at 720p.

## At a glance

| | |
|---|---|
| Model IDs | `seedance-2.0` · `seedance-2.0-fast` · `seedance-2.0-mini` |
| Calls | `POST /v1/videos/generations` → `GET /v1/videos/{request_id}` → `GET /v1/videos/{request_id}/content` |
| Base URL | `https://argolink.io/v1`, Bearer key in `Authorization` |
| Input modes | text · first frame · first + last frame · reference (images, video, audio in any mix) |
| Duration | 4–15 s in whole seconds, default 5 |
| Resolution | `seedance-2.0`: 480p, 720p, 1080p, 4k · Fast and Mini: 480p, 720p · default 720p |
| Aspect ratio | 21:9, 16:9, 4:3, 1:1, 3:4, 9:16 (default 16:9); frame modes also accept `adaptive` |
| References | up to 9 images, 3 videos, 3 audio clips, 15 in total; audio needs an image or video beside it |
| Prompt | required in every mode, up to 40,000 bytes |
| Sound | generated by default; `generate_audio: false` for a silent clip |
| Output | one MP4 per request; 16:9 at 720p is 1280×720, 1:1 is 960×960 |
| Not available | `seed`, `watermark: true`, `n` > 1 (all 400); editing or extending a video (on this API only `seedance-2.5` edits) |

All three accept the same modes and reference limits. They differ in resolution, speed and price per output second:

| `seedance-2.0-fast` | 480p, 720p | $0.042 | $0.091 | — | — | $0.0562 / $0.121 | quicker previews |

BytePlus positions them the same way: 2.0 for the highest quality, Fast to balance cost and speed, Mini for the best cost performance. ## Quick start

```bash
git clone https://github.com/haroldreyner9/seedance-2-0-api
cd seedance-2-0-api
export SEEDANCE_API_KEY=your-key        # create one in the ArgoLink console

bash examples/curl/text_to_video.sh "A paper boat drifts down a rain-filled gutter, macro tracking shot"
pip install requests && python examples/python/text_to_video.py
node examples/node/text_to_video.mjs    # Node 18+, no packages
```

Each script submits a job, prints the progress while it is `pending`, saves the MP4 and prints `usage`, the seconds you were billed for.

### cURL, call by call

```bash
BASE=https://argolink.io/v1

# 1. Submit: HTTP 202 with {"request_id": "..."}
curl $BASE/videos/generations \
  -H "Authorization: Bearer $SEEDANCE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "seedance-2.0", "prompt": "A hot-air balloon rises over terraced rice fields at dawn, slow aerial pull-back", "duration": 6, "resolution": "1080p", "aspect_ratio": "16:9"}'

# 2. Poll every 10-15 s: pending (progress 0-99) -> done | failed | expired
curl $BASE/videos/$REQUEST_ID -H "Authorization: Bearer $SEEDANCE_API_KEY"

# 3. Download once done (409 job_video_not_ready before that, 424 job_failed for a failed job)
curl -L $BASE/videos/$REQUEST_ID/content -H "Authorization: Bearer $SEEDANCE_API_KEY" -o balloon.mp4
```

That job is 6 × $0.28 = $1.68.

### Python

```python
from seedance_job import SeedanceJob   # examples/python/seedance_job.py, needs `requests`

job = SeedanceJob().run(
    {"model": "seedance-2.0-fast", "prompt": "A skateboarder carves an empty pool, fisheye lens, late afternoon sun",
     "duration": 5, "resolution": "720p", "aspect_ratio": "9:16"},
    "skate.mp4",
)
print(job["usage"])   # {'output_seconds': 5, 'reference_video_seconds': 0, 'billed_seconds': 5}
```

### Node.js

```js
import { SeedanceJob } from "./examples/node/seedance_job.mjs";

const job = await new SeedanceJob().run(
  { model: "seedance-2.0-mini", prompt: "Snow falls on a quiet harbor at night, boats rocking gently", resolution: "480p" },
  "harbor.mp4",
);
console.log(job.usage); // duration left out: renders and bills 5 s
```

## Modes and parameters

One endpoint serves every mode; the media fields in the body decide which one runs. Frame fields and reference lists cannot be mixed in one request.

| Mode | Send | Aspect ratio | Example |
|---|---|---|---|
| Text to video | `prompt` only | a fixed ratio, default 16:9 | [text_to_video.sh](./examples/curl/text_to_video.sh) |
| First frame | `start_image` | `adaptive` follows the frame; a fixed ratio crops it | [image_to_video.py](./examples/python/image_to_video.py) |
| First + last frame | `start_image` + `end_image` | as above; the last frame is fitted to the first | [first_last_frame_4k.sh](./examples/curl/first_last_frame_4k.sh) |
| Reference | `reference_images`, `reference_videos`, `reference_audios` | a fixed ratio, default 16:9 | [reference_to_video.mjs](./examples/node/reference_to_video.mjs) |

### Fields every mode takes

| Field | Type | Default | Rules |
|---|---|---|---|
| `model` | string | — | `seedance-2.0`, `seedance-2.0-fast` or `seedance-2.0-mini` |
| `prompt` | string | — | required; UTF-8, at most 40,000 bytes |
| `duration` | integer | 5 | 4–15 whole seconds; alias `seconds` |
| `resolution` | string | `720p` | `480p`, `720p` on all three; `1080p` and `4k` on `seedance-2.0` only |
| `aspect_ratio` | string | `16:9` | `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`; `adaptive` only with frames; alias `ratio` |
| `size` | string | — | `WIDTHxHEIGHT` instead of resolution + ratio: `1280x720` means 720p 16:9 |
| `generate_audio` | boolean | `true` | `false` returns a silent video |
| `n` | integer | 1 | only 1 |

Send one name per value: `duration` and `seconds` together are rejected, as is a `size` that contradicts `resolution` or `aspect_ratio`.

### Frames

| Field | Value | Notes |
|---|---|---|
| `start_image` | `{"url": "https://…"}` | JPEG or PNG, up to 20 MiB |
| `end_image` | `{"url": "https://…"}` | only together with `start_image`; its source ratio may differ from the first frame's |

```json
{
  "model": "seedance-2.0",
  "prompt": "The lantern flickers on as dusk falls over the same courtyard",
  "duration": 6,
  "resolution": "1080p",
  "aspect_ratio": "adaptive",
  "start_image": {"url": "https://example.com/courtyard-day.png"},
  "end_image": {"url": "https://example.com/courtyard-dusk.png"}
}
```

### References

| Field | Up to | Each asset | Billing |
|---|---|---|---|
| `reference_images` | 9 | JPEG or PNG, ≤ 20 MiB | free |
| `reference_videos` | 3 | 2–15 s, 15 s in total, 200–2160 px per side, ≤ 50 MB | its seconds are added to the bill |
| `reference_audios` | 3 | WAV or MP3, 2–15 s, 15 s in total, ≤ 15 MB | free |

Any mix fits as long as each list stays under its cap: 9 + 3 + 3 = 15 is a valid request. Name assets in the prompt as `@Image 1`, `@Video 2`, `@Audio 1`; numbers count from 1 inside each list. Naming is optional (unnamed assets are still used), and a number past the end of its list is rejected with 400.

### Local files

Every media field takes a public HTTPS URL; base64 data, multipart uploads and file IDs are rejected, and the whole JSON body must stay under 1 MiB. For a local file, ask for an upload ticket, `PUT` the bytes to `upload_url` with the declared `Content-Type`, and put the returned `media_url` in the request. Tickets are free and create no job; `upload_url` is valid for 15 minutes and `media_url` for seven days. [upload_then_reference.sh](./examples/curl/upload_then_reference.sh) does both steps.

```bash
curl https://argolink.io/v1/media/uploads \
  -H "Authorization: Bearer $SEEDANCE_API_KEY" -H "Content-Type: application/json" \
  -d '{"model": "seedance-2.0", "type": "image", "content_type": "image/png", "size_bytes": 48213}'
# -> {"upload_url": "...", "media_url": "...", "upload_expires_at": ..., "expires_at": ...}
```

## Job states and errors

| Status | Meaning | Fields worth reading |
|---|---|---|
| `pending` | queued or rendering | `progress` (0–99), `estimated_seconds_remaining` once there is a forecast |
| `done` | MP4 ready | `progress: 100`, `video.url`, `usage.billed_seconds` |
| `failed` | no video, not billed | `error.code`, `error.message`, `error.retryable`, `error.field` |
| `expired` | no video, not billed | — |

A job that finds no capacity within 10 minutes fails with `capacity_unavailable` (retryable); once rendering has started it waits for the result and gives up only after 24 hours (`generation_timeout`).

| HTTP | `error.code` | When |
|---|---|---|
| 400 | `field_invalid`, `json_invalid` | malformed body, non-HTTPS media URL, frames mixed with references |
| 400 | `request_unsupported` | the model can't do it: 1080p on Mini, a 16 s clip, audio-only references, a seed |
| 401 | — | missing or wrong key |
| 402 / 403 | — | balance too low, or the key's group has no video access |
| 404 | `video_request_not_found` | unknown `request_id`, or a key from another user |
| 409 | `job_video_not_ready` | content requested before `done` |
| 424 | `job_failed` | content requested for a failed job |
| 429 | — | concurrency or rate limit: retry when running jobs finish |
| 503 | `no_capacity` | retry after the `Retry-After` header; nothing charged |

Job failure codes: `invalid_input`, `content_policy_violation`, `copyright_violation`, `generation_failed`, `generation_timeout`, `capacity_unavailable`, `internal_error`, `cancelled`. When `retryable` is `true`, sending the same request again is safe.

## Prompting Seedance 2.0

These rules condense [BytePlus's Seedance 2.0 prompt guide](https://docs.byteplus.com/en/docs/modelark/seedance-2-0-prompt-guide):

- **Bind every subject to its asset** each time it appears ("the chef in @Image 1"), or define a label once and reuse it.
- **Write a shot list, not a paragraph.** "Shot 1: … Shot 2: …" in story order works better than exact timestamps, which the model follows unreliably.
- **One camera move per shot.** "slow push-in" or "lateral tracking", not push, pan and tilt at once.
- **Slow, specific motion** (which hand, how far, how fast) renders cleaner than sprints and jumps; show emotion through gestures instead of naming it.
- **Fewer assets often beat more.** BytePlus suggests 4–5: one or two character images, a scene image, a camera-motion video, an audio clip.
- **Sound has its own notation:** music in （…）, effects in <…>, dialogue in {…}, on-screen text in 【…】. Keep spoken lines in one language.
- **Close with constraints:** "keep it subtitle-free", "do not generate a logo", "do not generate a watermark".

Example (text only, 10 s):

```text
Shot 1: wide shot of a night market in the rain, a girl in a yellow raincoat weaves between stalls, slow lateral tracking.
Shot 2: close-up, she lifts a paper lantern and the light catches her face; she smiles slightly.
Shot 3: the camera pulls back to the whole street as the lanterns sway. (soft lo-fi beat) <rain on canvas awnings>
Cinematic texture, natural colors, keep it subtitle-free.
```

## Billing rules

- You pay the per-second rate of the model and resolution × billed seconds. Billed seconds = output seconds + the total length of any reference videos, with the fraction of a second dropped.
- Reference images, reference audio and uploads are free; the input mode does not change the rate.
- A request without `duration` renders and bills 5 seconds.
- Failed and expired jobs cost nothing. The charge is made once, when the job is first seen `done`, using `usage.billed_seconds`.
- Worked examples at the 2026-10-07 rates: 8 s at 1080p on `seedance-2.0` = $2.24; 4 s at 480p on Mini = $0.104; 6 s at 720p with a 3.5 s reference video = 9 s × $0.11 = $0.99.
- With long reference videos, compare totals rather than per-second rates: BytePlus and OpenRouter switch to a lower token rate ($4.3 per million at 480p–720p) when the input contains video, while ArgoLink bills those seconds at the normal rate.

## Coming from fal or OpenRouter

Request bodies written for either service can be sent as they are; each alias maps to one field:

| fal / OpenRouter name | Field here |
|---|---|
| `image_url` | `start_image` |
| `end_image_url` | `end_image` |
| `image_urls`, `video_urls`, `audio_urls` | `reference_images`, `reference_videos`, `reference_audios` |
| `frame_images` items with `frame_type` `first_frame` / `last_frame` | `start_image` / `end_image` |
| `input_references` items of type `image_url`, `video_url`, `audio_url` | the three reference lists |
| `size` such as `1280x720` | `resolution` + `aspect_ratio` |

Differences: `duration` is documented as an integer from 4 to 15, so send `6` rather than fal's `"6"` or `"auto"`; text and reference requests take a fixed ratio (`adaptive` is rejected there); `seed` is rejected; and results are polled at `/v1/videos/{request_id}` instead of a queue URL.

## FAQ

**How long does a Seedance 2.0 video take?**
A few minutes, longer when the queue is busy. OpenRouter's median over a week was about 3.4 minutes for 2.0 and 2 minutes for Fast and Mini. Poll the status instead of assuming a deadline.

**Which variant should I start with?**
Mini for drafting prompts ($0.026/s at 480p, so a 5-second test costs $0.13), then the same prompt on `seedance-2.0` at the resolution you need. Fast sits between them when turnaround matters more than the last step of quality.

**Can I get 4K?**
Yes, on `seedance-2.0` only, at $0.58/s, in every mode. BytePlus documents its 4K output as 10-bit H.265/HEVC, which some browsers cannot play; check the codec with `ffprobe` before you serve the file on the web.

**Can Seedance 2.0 edit or extend a video I already have?**
Not on this API: `omni_reference_task_type: "edit"` works only with `seedance-2.5`, and extension is not offered. BytePlus's own API exposes editing and extension for the 2.0 series.

**Why was my reference request rejected?**
The usual causes are audio sent without an image or video, more than 9 / 3 / 3 assets, a frame mixed with reference lists, or an `@Image 3` when only two images were sent. Faces can also be refused by content review, which fails the job with `content_policy_violation` and charges nothing.

**What does the cheapest real test cost?**
Mini at 480p for 4 seconds: 4 × $0.026 = $0.104.
